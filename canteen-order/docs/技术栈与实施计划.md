## 2. 架构与分层

```
[Swagger / H5 / 管理端]
          │ HTTPS  /api/v1
   Spring Security + JWT Filter
          │
   Controller（参数校验、返回 Result）
          │
   Service（业务编排、@Transactional）
          │
   Mapper（MyBatis-Plus / 自定义 SQL）
          │
   MySQL 8           Redis 7
   持久化/事务        缓存/会话/库存/幂等/延迟队列
```

分层约定：

- Controller 只做参数接收、校验、调用 Service；
- Service 承担事务边界，跨表业务集中在这里；
- Mapper 单表 CRUD 用 `BaseMapper`，库存与统计用自定义 SQL；
- Entity 不直接返回前端，统一转 VO；
- 统一返回 `Result<T>{code,message,data,traceId,timestamp}`。

包结构：`common / config / security / entity / mapper / dto / vo / service / controller / job / init`。

## 3. 核心方案

### 3.1 认证鉴权

| 项 | 落地 |
|---|---|
| Access Token | 30 分钟，携带 `userId / username / role / jti / type=access` |
| Refresh Token | 7 天，`type=refresh`，Redis `canteen:auth:refresh:{userId}` 保存当前有效值 |
| 刷新 | 轮换：校验 Redis 中保存的 Token 与请求一致，签发新双 Token 并覆盖；旧 Refresh 立即失效（实测返回 401） |
| 登出 | Access `jti` 写黑名单 `canteen:auth:black:{jti}`，TTL=剩余有效期；同时清 Refresh |
| 权限 | `/admin/**` 需 ADMIN，`/staff/**` 需 STAFF/ADMIN，其余需登录；公开路径白名单含菜品、菜单、档口、上传静态资源、Swagger、健康检查 |
| 密码 | BCrypt，登录失败统一提示「用户名或密码错误」 |
| 防刷 | `@RateLimit` 注解 + AOP + Redis 计数（登录 10 次/分钟） |
| 单端登录 | 配置 `single-login=false`（默认关闭，可按需开启） |

### 3.2 防超卖

1. 每日菜单初始化时把 `stock_left` 写入 `canteen:stock:menu:{menuId}`；
2. 下单先执行 Lua 原子预扣，不足直接抛 300103；
3. DB 执行 `UPDATE daily_menu SET stock_left = stock_left - n WHERE id=? AND stock_left >= n`；
4. DB 影响行数为 0 → 回滚 Redis 预扣并抛库存不足；
5. 取消 / 超时 / 退款 → `restoreStock` 回补 DB（`LEAST(stock_left+n, stock_total)`）与 Redis；
6. Redis 不可用时库存直接走 DB，保证可用性优先。

### 3.3 订单状态机

```
10 待支付 → 20 已支付 → 30 备餐中 → 40 可取餐 → 50 已完成
   │            │
   │取消/超时     │退款
   ▼            ▼
 60 已取消     70 已退款
```

- 唯一入口 `OrderService.transit()`，`OrderStatus.canTransitionTo()` 白名单校验；
- `order_info.version` 乐观锁，冲突抛 409；
- 每次流转写 `order_status_log`（操作人、前后状态、备注）；
- 超时取消：下单写 `canteen:order:delay` ZSet，`OrderTimeoutJob` 每 10 秒轮询，`ZREM` 抢占保证多实例只执行一次，取消前二次确认仍为待支付；
- 取餐核销：校验状态必须为「可取餐」+ 取餐码一致，成功后置为已完成。

### 3.4 幂等

| 场景 | 方案 |
|---|---|
| 下单 | `requestId` 必填；Redis `SETNX` 30 分钟 + 唯一索引 `uk_user_request(user_id, request_id)`；重复请求回查已有订单返回 |
| 支付回调 | `payment_record.trade_no` 唯一索引；重复回调直接返回 `success` |
| 退款 | `refund_record.refund_no` 唯一；状态必须为已支付/备餐中 |
| 订单操作 | 状态机 + 乐观锁兜底 |

### 3.5 缓存与降级

| Key | 类型 | TTL | 用途 |
|---|---|---|---|
| `canteen:dish:category` | String(JSON) | 30 分钟 | 分类列表 |
| `canteen:dish:detail:{id}` | String(JSON) | 30 分钟 + 随机抖动 | 菜品详情 |
| `canteen:dish:null:{id}` | String | 60 秒 | 空值防穿透 |
| `canteen:menu:today:{yyyy-MM-dd}` | String(JSON) | 60 秒 + 抖动 | 今日菜单（库存实时叠加） |
| `canteen:cart:{userId}` | Hash | 7 天 | 购物车 `dishId:specId → qty` |
| `canteen:auth:refresh:{userId}` | String | 7 天 | Refresh Token |
| `canteen:auth:black:{jti}` | String | 剩余有效期 | 登出黑名单 |
| `canteen:order:idem:{userId}:{requestId}` | String | 30 分钟 | 下单幂等 |
| `canteen:order:delay` | ZSet | — | 超时取消延迟队列 |
| `canteen:captcha:{key}` | String | 120 秒 | 图形验证码（默认关闭） |

降级策略：Redis 异常时缓存按未命中处理、库存与购物车走 DB、JWT 过滤器跳过黑名单/单端校验；Refresh 接口 fail-closed（会话服务不可用则要求重新登录）。

### 3.6 可观测性

- `TraceIdFilter` 为每个请求生成 traceId，写入 MDC 并回传 `X-Trace-Id`；
- 全局异常处理记录 traceId，便于按日志定位；
- `@OperLog` + AOP 写 `sys_oper_log`（模块、动作、参数、耗时、IP、结果）；
- Actuator 暴露 `health/info/metrics`；
- 日志文件 `./logs/canteen-order.log`。

## 7. 与初版规划的差异

| 项 | 初版规划 | 实际落地 | 原因 |
|---|---|---|---|
| JDK | 21 | 11 | 用户明确指定 JDK 11 + Maven 11 |
| Spring Boot | 3.5.x | 2.7.18 | JDK 11 不兼容 Boot 3 |
| 分布式锁/延迟队列 | Redisson | 原生 SETNX + Lua、ZSet | 减少依赖，Redis 故障可降级 |
| 对象映射 | MapStruct | 手写转换 | 类数量可控，避免额外注解处理器 |
| 数据库版本管理 | Flyway 10 | Flyway 9.22.3 + flyway-mysql | Boot 2.7 依赖管理上限 |
| RBAC | 4 张表 | `role_code` 单列 | 三角色场景足够 |
| 部署 | Docker Compose | 直接 jar + 外部 MySQL/Redis | 用户已有服务器，不引入容器 |
| 前端 | Vue3 管理端 + H5 | 仅后端 + Swagger | 用户未确认前端范围 |
| 导出 | Excel | CSV（UTF-8 BOM） | 无 POI 依赖，Excel 可直接打开 |

## 8. 后续建议

1. **前端**：管理端（Vue3 + Element Plus）优先级最高，用户端 H5（Vue3 + Vant）次之；接口已全部就绪。
2. **支付**：当前为余额支付 + 模拟网关；接真实微信/支付宝时替换 `PaymentService.mockCallback`，保留验签与幂等结构。
3. **可观测性**：接入 Prometheus + Grafana，补充慢 SQL 与 JVM 指标。
4. **测试**：补 Service 层单测（下单、库存、状态机、幂等）与 Testcontainers 集成测试；用 JMeter 验证 200 并发不超卖。
5. **安全**：生产环境把数据库密码、JWT secret、支付 secret 改为环境变量；CORS 收敛为具体域名；Swagger 加访问控制。

## 9. 风险与注意事项

| 风险 | 应对 |
|---|---|
| MySQL 远程 root 未授权 | 服务器执行授权 SQL，检查 bind-address 与安全组（README 4.1） |
| Redis 单点故障 | 已做降级；生产建议主从 + 哨兵 |
| Redis 与 DB 库存短暂不一致 | 以 DB 扣减结果为准，失败回滚 Redis；每日对账 |
| 延迟队列单点 | ZSet + `ZREM` 抢占已支持多实例；量大时再换 MQ |
| 端口冲突 | 用 `--server.port` 覆盖 |
| 明文密钥入库 | 上线前改环境变量 |
